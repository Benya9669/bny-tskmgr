# SMTP и подтверждение email

Начиная с `0.0.1`, новый аккаунт нельзя использовать до подтверждения email. TaskFlow отправляет одноразовую ссылку через настроенный SMTP-сервер; без SMTP регистрация возвращает `503` и полностью откатывается.

## Настройка

Минимальная конфигурация `.env`:

```dotenv
TASKFLOW_PUBLIC_URL=https://tasks.example.com
TASKFLOW_SMTP_HOST=smtp.example.com
TASKFLOW_SMTP_PORT=587
TASKFLOW_SMTP_MODE=starttls
TASKFLOW_SMTP_USERNAME=taskflow@example.com
TASKFLOW_SMTP_PASSWORD=replace-with-an-app-password
TASKFLOW_SMTP_FROM=taskflow@example.com
TASKFLOW_VERIFICATION_TTL_HOURS=24
```

Режимы подключения:

- `starttls` — рекомендуемый вариант, обычно порт 587;
- `ssl` — TLS сразу после подключения, обычно порт 465;
- `plain` — только для доверенного локального SMTP relay в изолированной сети.

`TASKFLOW_PUBLIC_URL` должен быть внешним HTTPS-адресом TaskFlow без завершающего `/`. Именно на него ведёт ссылка из письма. Не помещайте пароль SMTP в Compose или Git: храните его в `.env` с ограниченными правами либо в secret manager.

## Проверка

1. Запустите TaskFlow с настроенным SMTP.
2. Зарегистрируйте отдельный тестовый адрес.
3. Убедитесь, что до перехода по ссылке вход возвращает сообщение о неподтверждённом email.
4. Перейдите по ссылке и проверьте автоматический вход.
5. Повторный переход по той же ссылке должен завершиться ошибкой: токен одноразовый.

Токен действует по умолчанию 24 часа и хранится в базе только как SHA-256 хеш. Повторная отправка доступна не чаще одного раза в минуту и возвращает одинаковый ответ для существующих и неизвестных адресов, чтобы не раскрывать список пользователей.

## Обновление существующей установки

Миграция схемы `1 → 2` добавляет статус подтверждения и таблицу одноразовых токенов. Все аккаунты, созданные до обновления, помечаются подтверждёнными, поэтому владельцы существующих установок не теряют доступ. Подтверждение обязательно только для новых регистраций.

Перед обновлением создайте backup по `docs/operations.md`. После запуска проверьте, что `/api/health` возвращает `schema_version: 2`.

## Диагностика

- `email_delivery_failed` при регистрации — проверьте host, port, режим TLS, sender и данные авторизации.
- Письмо принято SMTP, но не доставлено — проверьте spam, SPF, DKIM и DMARC домена отправителя.
- Ссылка ведёт на localhost или HTTP — исправьте `TASKFLOW_PUBLIC_URL` и запросите новое письмо.
- Не используйте основной пароль почтового аккаунта, если провайдер поддерживает отдельные app passwords.

TaskFlow не журналирует пароль SMTP, полный токен или содержимое письма.
