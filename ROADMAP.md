# TaskFlow Roadmap

Roadmap описывает путь от первого работоспособного self-hosted релиза до стабильного веб-продукта и Android-клиента. Версии следуют SemVer: до `1.0.0` минорная версия может менять внутренние контракты, а patch-релизы должны сохранять совместимость данных и API.

Обозначения: `[x]` готово, `[~]` реализовано частично, `[ ]` запланировано.

## Принципы релиза

Каждая версия считается готовой только если:

1. Существующие пользовательские данные сохраняются при обновлении.
2. API и UI проходят автоматические проверки.
3. Docker-образ собирается для `linux/amd64` и `linux/arm64`.
4. Есть понятные инструкции запуска, обновления и восстановления.
5. В репозитории и образе нет секретов, тестовых данных и локальных макетов.
6. Критические действия требуют подтверждения или имеют обратимый результат.

## 0.0.1 — базовый работоспособный продукт

Цель: один пользователь может развернуть TaskFlow, зарегистрироваться и ежедневно вести задачи и проекты через браузер.

### Пользовательские функции

- [x] Регистрация и вход по email и паролю.
- [x] Обязательное подтверждение email через настраиваемый SMTP перед первым входом.
- [x] Изоляция данных разных пользователей.
- [x] Создание, просмотр и редактирование задач.
- [x] Мягкое удаление задач.
- [x] Приоритет, описание, дата планирования и оценка времени.
- [x] Представления «Сегодня», «Входящие», «Все задачи», «Выполненные».
- [x] Создание проектов и фильтрация задач по проекту.
- [x] Переименование, изменение цвета и удаление проекта без потери его задач.
- [x] Явный выбор статуса задачи: входящие, запланировано, в работе, выполнено.
- [x] Корректная обработка просроченных и незапланированных задач.
- [x] Адаптивный интерфейс.
- [x] Светлая и тёмная темы.
- [x] Канбан-доска по статусам с drag-and-drop и фильтрацией по проекту.
- [x] Понятные loading/error/empty состояния для основных действий.

### Данные и API

- [x] SQLite с foreign keys и WAL.
- [x] Версионирование API через `/api/v1`.
- [x] UUID, optimistic locking и tombstone-удаления.
- [x] Инкрементальный endpoint `/sync` для будущего Android-клиента.
- [x] Проверка и нормализация всех дат и внешних идентификаторов.
- [x] Схема БД с номером версии и защитой от несовместимого downgrade.
- [x] Машиночитаемая спецификация OpenAPI.

### Эксплуатация и качество

- [x] Dockerfile, development Compose и release Compose.
- [x] Healthcheck.
- [x] GitHub Actions для тестов и публикации GHCR.
- [x] Автотесты авторизации, CRUD и конфликтов синхронизации.
- [x] Тесты проектов, фильтров, валидации и изоляции пользователей.
- [x] Graceful shutdown и структурированные HTTP-логи.
- [x] Инструкция безопасного обновления и резервного копирования SQLite.
- [x] Версия приложения в API, образе и интерфейсе.

### Release gate 0.0.1

- [x] Все функциональные пункты `0.0.1` закрыты либо явно перенесены с объяснением.
- [x] `python -m unittest discover -v` проходит.
- [x] Оба Compose-файла проходят `docker compose config`.
- [x] Локальный Docker-образ собирается и отвечает `200` на `/api/health`.
- [x] Проверен перезапуск новой сборки с сохранением тестовой базы.
- [x] Подготовлен `CHANGELOG.md`.
- [x] Финальная ручная приёмка пройдена, выпуск `v0.0.1` подтверждён владельцем проекта.

Цель: убрать основные трения после первых недель реального использования.

- [ ] Быстрое добавление задачи с клавиатуры.
- [ ] Поиск и фильтры по проекту, статусу, приоритету и датам.
- [ ] Перенос задачи между днями и проектами.

- [ ] Подзадачи и чек-листы.
- [ ] Архив проектов.
- [ ] Экспорт и импорт JSON.
- [ ] Улучшенная доступность клавиатуры и screen reader.
- [ ] Набор browser smoke-тестов.

- [ ] Повторяющиеся задачи.
- [ ] Напоминания в браузере.
- [ ] Теги и сохранённые фильтры.
- [ ] Оценка доступного времени и дневной нагрузки.
- [ ] Режим фокуса и простой таймер.
- [ ] История изменений задачи.

## 0.2.0 — offline-first и стабильный мобильный контракт

Цель: заморозить API-контракт, необходимый для разработки Android-клиента.

- [ ] OpenAPI-контракт признан стабильным для `v1`.
- [ ] Refresh-токены, список сессий и отзыв доступа устройства.
- [ ] Пакетная отправка локальных изменений.
- [ ] Идемпотентные команды с client mutation ID.
- [ ] Формализованная стратегия разрешения конфликтов.
- [ ] Пагинация, сжатие и ограничение размера sync-ответа.
- [ ] Учёт часового пояса пользователя.
- [ ] Контрактные тесты для Kotlin-клиента.

## 0.3.0 — Android beta

- [ ] Kotlin + Jetpack Compose.

- [ ] Безопасное хранение токенов через Android Keystore.

## 1.0.0 — стабильный self-hosted продукт

Цель: долгосрочно поддерживаемая версия с предсказуемыми обновлениями.

- [ ] Стабильные Web API и схема данных.
- [ ] Автоматические миграции с документированным rollback-планом.
- [ ] Политика резервного копирования и проверенный restore flow.
- [ ] Web и Android покрывают основной пользовательский сценарий.
- [ ] Документация reverse proxy, TLS, обновления и мониторинга.
- [ ] Security review, rate limiting и аудит зависимостей/образов.
- [ ] Политика совместимости и цикл выпуска исправлений.

## После 1.0

Возможные направления: CalDAV, интеграции с календарями, вложения через S3-compatible storage, публичный API/webhooks, desktop-клиент и end-to-end encryption для приватных пространств. Эти функции не должны задерживать стабильный `1.0.0`.
