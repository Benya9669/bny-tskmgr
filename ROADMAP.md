# TaskFlow Roadmap

Roadmap описывает путь от первого работоспособного self-hosted релиза до стабильного веб-продукта и Android-клиента. Версии следуют SemVer: до `1.0.0` минорная версия может менять внутренние контракты, а patch-релизы должны сохранять совместимость данных и API.

Обозначения: `[x]` готово, `[~]` реализовано частично, `[ ]` запланировано.

## Принципы релиза

Каждая версия считается готовой только если:

1. Существующие пользовательские данные сохраняются при обновлении.
2. API и UI проходят автоматические проверки.
3. Docker-образ собирается для `linux/amd64` и `linux/arm64`.
4. Есть понятные инструкции запуска, обновления и восстановления.
5. В репозитории и образе нет секретов, тестовых данных и локальных макетов.
6. Критические действия требуют подтверждения или имеют обратимый результат.

## 0.2.0 — offline-first и стабильный мобильный контракт

Цель: заморозить API-контракт, необходимый для разработки Android-клиента.

- [x] Устанавливаемое PWA: Web App Manifest, адаптивные иконки, режим `standalone` и корректная установка на Android и desktop.
- [x] Service Worker с офлайн-доступом к оболочке приложения, явным экраном состояния сети и безопасным обновлением без потери несохранённых данных.
- [x] Локальное хранилище PWA для чтения и изменения задач без сети с последующей синхронизацией и понятным отображением конфликтов.
- [x] OpenAPI-контракт признан стабильным для `v1` и закреплён контрактными тестами.
- [x] Refresh-токены с ротацией, список сессий и отзыв доступа устройства.
- [x] Пакетная отправка локальных изменений задач.
- [x] Идемпотентные команды задач с client mutation ID.
- [x] Формализованная стратегия разрешения конфликтов задач: пользователь выбирает серверную или локальную версию; локальная версия повторяется с актуальной версией задачи.
- [x] Пагинация, gzip-сжатие и ограничение размера sync-ответа через bounded change stream (`limit <= 500`).
- [x] Учёт часового пояса пользователя через IANA timezone в профиле.
- [x] Контрактные тесты API для Kotlin-клиента: sync pagination/gzip и обязательные offline/auth endpoints.

## 0.3.0 — Android beta

Цель: ежедневная работа с задачами без постоянного подключения к серверу.

Детальный план и актуальные отметки находятся в [`../android/ROADMAP.md`](../android/ROADMAP.md). Android-клиент остаётся отдельным репозиторием и использует стабильный контракт этого репозитория из `docs/openapi.json`.

- [x] Kotlin + Jetpack Compose: Gradle-каркас, общая дизайн-система TaskFlow и адаптивный app shell.
- [x] Room как локальный источник данных для задач, проектов, канбан-колонок, sync-курсора и durable outbox.
- [x] WorkManager для фоновой Android-синхронизации: unique network job, retry, batch push и pull sync.
- [x] Android сохраняет version conflicts в Room и предлагает выбрать серверную версию либо повторить локальную с актуальной версией.
- [~] Android `0.3.0-alpha`: read-only проекты, offline-редактор описания/проекта/дат и локальные фильтры задач по проекту, статусу и приоритету; product UX ещё развивается до public beta.
- [x] Android: регистрация с подтверждением email, task deep links, Share text-to-inbox и локальные due-date уведомления.
- [x] Android beta: instrumented sync tests покрывают pagination и refresh token через MockWebServer.
- [x] Android beta: mutation replay, Room v1-to-v2 migration и email verification link покрыты и проверены на AVD.
- [x] Android beta: Compose UI-тесты покрывают login, offline inbox create и разрешение version conflict.
- [x] Android beta: проверены light/dark и wide layouts, E2E с чистым `v0.2.0` и debug APK hygiene audit.
- [x] Базовый Retrofit/Moshi-контракт auth/sync/mutations и безопасное хранение токенов через Android Keystore.
- [x] Login, восстановление локальной Android-сессии, регистрация и подтверждение email.
- [x] Pull sync задач, проектов и колонок с pagination/tombstones в Room.
- [~] «Сегодня», «Входящие», read-only «Проекты» и редактор задачи работают из Room; UX и project management запланированы в Android `0.3.0`.
- [x] Offline-создание, редактирование заголовка/приоритета, завершение и удаление задач с durable outbox и batch mutation push при запуске/refresh.
- [x] Deep links и системная кнопка «Поделиться в TaskFlow».
- [x] Локальные уведомления.

## После 1.0

Возможные направления: CalDAV, интеграции с календарями, вложения через S3-compatible storage, публичный API/webhooks, desktop-клиент и end-to-end encryption для приватных пространств. Эти функции не должны задерживать стабильный `1.0.0`.
